# KNOT: A Knowledge Entanglement Benchmark for Robust Unlearning Evaluation

Official repository for the NeurIPS 2026 Evaluations & Datasets Track paper:

> **KNOT: A Knowledge Entanglement Benchmark for Robust Unlearning Evaluation**
> Mengyang Li, Jingwen Wang, Yu Zhang, Shuang Liu, Zhong Zhang

Large language model (LLM) unlearning aims to selectively remove specific knowledge while preserving model utility. Existing benchmarks such as TOFU, WMDP, and MUSE evaluate unlearning on semantically disjoint forget and retain sets, making the task artificially easy. KNOT formalizes knowledge entanglement at three levels — **entity**, **concept**, and **skill** — and provides a benchmark of ~5,300 forget, ~9,800 retain, and ~5,000 boundary QA pairs, each annotated with a quantitative entanglement score. Evaluation of seven methods shows that (a) all methods degrade severely under high entanglement, (b) the coreset effect reported on standard benchmarks vanishes, and (c) existing metrics miss critical boundary behavior. We propose **Boundary Precision (BP)** and **Boundary Recall (BR)** to fill this gap.

- **Dataset (HuggingFace)**: https://huggingface.co/datasets/mochp/KNOT
- **Croissant metadata**: [`dataset/croissant_rai_KNOT.json`](dataset/croissant_rai_KNOT.json)

## Running the Pipeline

Run all steps in order (checkpoint-based; completed steps are skipped on re-run):

```bash
cd code
bash run_all.sh
```

Execution order (see [`code/README.md`](code/README.md) for details):

1. **Entity** — `query_wikidata_entities.py` (LLM generates entity profiles in the Wikidata property schema), then `generate_entity_qa.py`
2. **Concept** — `generate_concept_list.py`, then `generate_concept_qa.py`
3. **Skill** — `generate_skill_qa.py`
4. **Dedup & verification** — `dedup.py` (MinHash LSH), then `verify_qa.py`
5. **Scoring** — `compute_entanglement_scores.py`, `compute_kg_distance.py`, `compute_llm_judge_score.py`, `finalize_scores.py`
6. **Stats** — `generate_stats.py`

## Data Provenance

All data in KNOT is **generated by DeepSeek-V3.2** (API model `deepseek-chat`):

- **KNOT-Entity**: the model relies on its own knowledge of 290 well-known public figures to produce personal/professional knowledge triples (using the Wikidata property *schema*) and ~100-word short biographies; QA pairs are then generated from these triples and biographies. **No Wikidata endpoint is queried and no Wikipedia text is read.**
- **KNOT-Concept**: 150 dual-use scientific concepts within the WMDP topic scope (biosecurity, cybersecurity, chemistry), with forget / retain / boundary QA pairs about harmful uses, legitimate uses, and shared mechanisms.
- **KNOT-Skill**: Racket vs. Python programming QA pairs.
- **Quality control**: forget and boundary pairs are factually verified by DeepSeek and pairs with verification confidence below 0.7 are dropped; retain pairs are deduplicated (MinHash LSH) but not LLM-verified. Entanglement scores use `all-MiniLM-L6-v2` sentence-embedding cosine similarity; the Entity KG component is a per-entity knowledge-triple structural score (shared objects, bridging via other entities, content-word Jaccard fallback), not a Wikidata shortest-path distance.

## Safety Notes

- KNOT-Concept contains dual-use scientific content (biosecurity, cybersecurity, chemistry). All items follow the WMDP threat model and are conceptual rather than operational; operational specifics were removed during generation.
- QA pairs about real public figures in KNOT-Entity are synthetically generated by DeepSeek-V3.2 from its internal knowledge; some statements may be inaccurate, and no real private information (contact, financial, or biometric) about any individual is included.
